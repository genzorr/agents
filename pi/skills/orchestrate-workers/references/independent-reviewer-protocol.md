# Independent Reviewer Protocol

Use only for an explicit operator review request naming the task/acceptance target. Review is read-only and performed by a separate fresh-context leaf with no implementation ownership or delegation. Use the resolved reviewer profile; creation and reuse never authorize settings changes.

Dispatch after integration, owner diff inspection and required checks. Stabilize the exact target and decision-bearing dependencies through existing revisions or a recoverable scoped snapshot; disjoint work may continue. Send the operator goal/request, criteria, exact target, relevant interfaces/constraints, evidence locations, permitted inspection commands, risks and immediate-parent return route. Do not send only the implementer's summary.

Require inspection of the actual complete target. On a correction round, reuse valid prior coverage only after recovering the exact reviewed baseline and inspecting the entire subsequent delta and affected interfaces. Missing continuity requires expanded inspection. A verdict never covers unseen later edits.

Return ship, fix-first or rethink with precise findings, decisive evidence and residual limits. Incomplete execution returns blocked or failed, not acceptance. Reviewer mutation voids the verdict; preserve evidence and resolve restoration within authority before accepting the target. Do not claim hard read-only isolation unless the host supplies it.

The coordinator resolves corrections and integration; workers perform authorized repairs. Requested final-state review requires closure of acceptance-critical findings and review of later material deltas before affected acceptance. Continue unaffected authorized work while review is pending. Reuse a compatible reviewer across rounds; independence comes from separate identity, fresh context and no implementation ownership, not a model name. The reviewer reports only to its immediate coordinator.
