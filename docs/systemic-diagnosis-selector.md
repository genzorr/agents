# Systemic Diagnosis Selector

Open this reference only after the user explicitly requests the experimental `systemic-diagnosis` lens. An ordinary recurring or cross-boundary symptom does not activate it. Select the smallest useful lens; do not run every branch or force a diagram.

| Situation | Start with |
| --- | --- |
| One event may be part of a recurrence | Event → pattern → structure → assumption scan |
| Effects cross boundaries or arrive late | Causal map with material delays and feedback |
| Throughput or outcome gap has several plausible causes | Constraint lens without presuming one constraint |
| People disagree about a causal chain | Evidence labels, refutation, and rival explanations |
| A decision needs an actionable next step | Cheapest discriminating test or experiment routing |

Progressive disclosure:

1. Use breadth before depth: frame the outcome gap, boundary, actors, and time horizon.
2. Map only material actors/components, rules, ownership, incentives, capacity, delays, and causal links.
3. Mark load-bearing claims as observed/measured, inferred, or hypothesized.
4. Test the branch most likely to change the conclusion; keep refuted branches visible.
5. Separate symptom relief from mechanism change, then update the map and confidence as evidence arrives.

The selector is a helper for an active driver, not a router or workflow. `diagnose`, `review-change`,
`design-experiment`, and `prepare-dynamic-workflow` retain their existing ownership.
