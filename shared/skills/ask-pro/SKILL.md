# Ask Pro

Prepare the handoff, not the answer. Recover the user's intended outcome, questions, selected decisions, constraints, relevant steering and requested deliverables from available context. Preserve breadth when the task calls for independent discovery, verification, refinement, decisions or planning; do not force a recommendation or plan when unrequested. State the remaining gap and include material contrary evidence. Distinguish primary evidence (source, tests, configuration, direct measurements and provenance), requirements, working synthesis, hypotheses, selected decisions, preferences, assumptions and unknowns. Ask for evidence-backed challenge to an unsound framing while allowing uncertainty or a no-decision result. Distinguish a supported fact from the necessity of a proposed addition or constraint for the user’s outcome. A recommendation does not change the user's goal or authorize implementation. Resolve local facts first; ask only when a missing user-owned input materially changes the handoff or makes it misleading, otherwise disclose a reasonable assumption.

For research, preserve the stage and programme outcome: baseline selection chooses an established method; establishment produces a credible reference result; faithful reproduction retains essential method and evaluation semantics; adaptation identifies deviations and comparability; diagnosis explains a gap; novel improvement introduces a contribution. An established baseline need not be novel. Expose a mismatch when available hooks cannot support essential components rather than stripping them to fit. Preserve an explicitly requested causal scout. For experiments distinguish coherent-strategy utility, interactions and component attribution; match treatments and measurements to the claim. A strategy can be tested before isolated attribution, and a package result does not establish component causation. Scope prerequisites and deferrals to the action or claim they support; explain what remains unanswered and why.

For plain external research, return a directly usable prompt in chat by default. Request the research result, not another prompt. Include the relevant decision or outcome, primary sources, scope, evidence standard, proportional sufficiency bar, and unresolved or stop condition. Do not impose GitHub publication, a saved prompt, attachments or a downloadable report unless the user or an already-authorized workflow requires them.

## Pro consultation

Use this route for a requested manual Pro consultation, including repository-only, local-only and mixed evidence. Choose the target chat from existing context: explicit user choice wins; an identifiable consultation continuing the same question can receive a follow-up; a distinct question or independent reassessment generally needs a fresh chat with sufficient context. Revise an unsent draft into one complete prompt, not an addendum. Generated files do not prove submission. For a follow-up, identify new evidence, questions and superseded assumptions without assuming unconfirmed prior delivery. Do not create a tracking system or repeatedly confirm known status.

Select relevant primary evidence and material contrary evidence with provenance, versions and limitations. Keep raw observations distinct from summaries and label prior AI reasoning as synthesis. Include required and optional inputs, authoritative starting points, and what to do if evidence is inaccessible: report the gap rather than guess. Explain which snapshot is authoritative when attachments and repository evidence differ, and preserve material truncation or collection limitations. Ask Pro to inspect relevant sources directly and cite repository, commit, path and lines where possible, expanding beyond starting points when a concrete dependency matters. For change review include base and head. State any access uncertainty; this agent's access does not prove Pro's access.

Make repository code needed for the consultation available through GitHub at an exact commit. The operator grants standing permission for commits and normal pushes necessary to prepare Pro consultations, including implicit skill selection: inspect the relevant diff, preserve unrelated work, and use an appropriate existing or WIP feature branch and configured remote without asking again. This grants no merge, force push, branch deletion, release or unrelated publication. Respect explicit task restrictions, privacy and secrets rules, branch protection and sandbox/Auto-review enforcement; do not change permission profiles. A successful push and repository, branch and SHA normally suffice. Use a focused remote-ref or access check for concrete uncertainty, not exhaustive file or hash checks. A failed or uncertain push is not readiness: establish actual status before retrying or claiming availability.

For nonrepository attachments, prepare one inputs ZIP only when needed; small evidence may be inline. Include relevant logs, measurements, images or reports, not a duplicate of available repository source. Preserve filenames and relative structure, a compact provenance and code-version inventory, and material omissions. Exclude credentials, unrelated and private inputs outside the authorized scope. Check archive integrity and required-file presence proportionally. Repository-only, local-only and mixed evidence are all supported.

Write a directly pasteable prompt that identifies the outcome, relevant evidence and authority, questions, scope, evidence standard, sufficiency and unresolved conditions. Preserve requested output breadth and filenames. Instruct Pro to keep repositories and external systems read-only: it may produce reports, proposed patches or replacement artifacts, but must not apply changes or create commits, branches, issues or PRs. The preparation agent's publishing authority is not delegated to Pro.

Request concise response text and a downloadable Markdown report unless the user requests another form. Request PDF only on explicit user request. For one final deliverable, request a direct link; for two or more final deliverables, including the report, request one ZIP containing all of them with filenames and relative links preserved, and concise chat text. Do not include temporary work or require an extra report download outside the ZIP. If file generation or archive access is unavailable, disclose it and provide a usable text fallback without claiming packaging succeeded.

Before handoff, check that the requested outputs cover the intended outcome and that linked files, attachment names and versions agree. Give the human the exact target chat, prompt, inputs ZIP if needed, and repository/ref/SHA and access instructions where applicable; report any limitation affecting readiness. Keep the original prompt with existing task context; do not imply it was sent. Route a returned Pro answer to `answer-pro`.
