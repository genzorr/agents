# Independent Reviewer Protocol

Load for an actual task-scoped independent-review request, including the standard feature launch's request. That request authorizes this named delegation without another approval. The reviewer recommends a disposition; feature acceptance/validation remains outside the implementing owner. Native parentage does not transfer authority, and `ship` does not close a task or authorize merge/adoption.

## Target and packet

Review at the named checkpoint with evidence due then. Source/Protocol review can precede scientific execution; completed delivery requires the mandated final coverage. Bind a recoverable target: source/spec revisions, relevant uncommitted content, decision-bearing artifacts/environment and criteria. Serialize overlapping writers or use an authorized snapshot; disjoint work may continue. Do not inventory unrelated state or rerun valid worker checks as preparation ceremony.

Send the user request/provenance, original intended need and validation claim, acceptance actor, complete target/interfaces, actual source/artifact/evidence locations, material uncertainty, permitted non-mutating commands and immediate-parent native return. Provide actual evidence before producer interpretation, with read-only/no-delegation instructions.

Use a separate compatible reviewer with no implementation ownership. New reviewers receive no parent history. An advisor who shaped the candidate cannot independently review it. Existing-task messages omit settings fields, including `model` and `thinking`. Return only to the native parent; it forwards the attributable verdict/basis to the actual acceptor. No higher-orchestrator callback follows.

Claim hard read-only isolation only when established by the product. Under broader permissions proceed only when hard isolation is unnecessary; compare relevant mutation-sensitive state proportionately and disclose limits. Tests can mutate state: necessary execution needs authority and isolation protecting the target. Distinguish concurrent authorized writes from reviewer mutation.

## Coverage, correction and result

Initially inspect actual files/artifacts and the complete target diff with decision-critical dependencies. Assess criteria as satisfied, failed, not assessed or inapplicable with reason. Challenge wrong behavior, ineffective expectations and missing coverage, including a mismatch between a narrow contract and the original need. Sample only interchangeable artifacts with basis/limits. State what intended-use validation the evidence establishes and what remains for the orchestrator/user.

For corrections recover the exact baseline, findings and applicable coverage. Inspect the complete subsequent delta, affected interfaces/invariants/consumers and new verification. Carry still-applicable coverage; expand when recovery/impact requires it. Compaction alone does not erase coverage. Reuse the reviewer; do not review every edit or recreate it per phase. Critical findings require independent confirmation; requested final-state review includes affected later target changes, which owner checks cannot independently clear.

Keep repair with the executor/original compatible worker. Return an attributable recommendation tied to exact target and carried/new coverage: `ship`, `fix-first`, `rethink`, `blocked`, `failed` or `voided`, with decisive findings, gaps and residual risk. `ship` supports readiness; `fix-first` requires correction; `rethink` returns a consequential decision; `blocked` means review could not complete; `failed` supplies no review evidence; `voided` discards an invalid review. Missing necessary evidence prevents a supported verdict. Passing checks establish only their actual claim; a positive verdict cannot replace the orchestrator's assessment and intended-use validation.

For reviewer mutation preserve evidence, void the verdict and recycle the reviewer. Restore only within authority while protecting foreign work, then establish the affected baseline; unresolved restoration/attribution prevents reliance on that review.

Reuse one compatible idle reviewer across corrections; never assign concurrent reviews. When continuity is uncertain recover identity/disposition, exact target, findings/coverage and profile; routine rounds carry deltas. Recycle for incompatible role/profile/project/checkout/trust/authority/isolation, implementation ownership, unreachable state, irrecoverable anchoring, repeated critical misses or explicit fresh opinion, not time/compaction alone.

Continue unaffected work while required review is pending; only an authorized task-scoped waiver removes it. The actual acceptor resolves findings, checks evidence applicability and performs/obtains missing intended-use validation before recording completed-scope acceptance/closure. Owner/reviewer completion and transport acceptance alone establish none of those decisions. Merge/adoption return to the user in the orchestrator chat.
