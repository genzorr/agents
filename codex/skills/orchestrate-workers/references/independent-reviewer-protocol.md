# Independent Reviewer Protocol

Load for an actual task-scoped independent-review request, including the standard feature launch's request. That request authorizes this named delegation without another approval. The reviewer recommends a disposition; feature acceptance/validation remains outside the implementing owner. Native parentage does not transfer authority, and `ship` does not close a task or authorize merge/adoption.

## Target and packet

Review at the named checkpoint with evidence due then. Source/Protocol review can precede scientific execution. Normal feature review covers the final delivered target before readiness unless the user explicitly waives review; manual review follows its actual checkpoint mandate without inheriting an unrequested final-state review. Bind a recoverable target: source/spec revisions, relevant uncommitted content, decision-bearing artifacts/environment and criteria. Serialize overlapping writers or use an authorized snapshot; disjoint work may continue. Do not inventory unrelated state or rerun valid worker checks as preparation ceremony.

Send the user request/provenance, original intended need and validation claim, acceptance actor, complete target/interfaces, actual source/artifact/evidence locations, material uncertainty, permitted non-mutating commands and immediate-parent native return. For whole-change review provide source/contracts/original evidence before producer interpretation or old positive conclusions; for fix verification provide original failure scenarios immediately. Include read-only/no-delegation instructions.

Use a fresh reviewer identity/context for every new substantive review request, including requested correction reviews, with no implementation ownership or parent history. Clarification of an issued report can retain its context. An advisor who shaped the candidate cannot independently review it. Existing-task messages omit settings fields, including `model` and `thinking`. Return only to the native parent; it forwards the attributable verdict/basis to the actual acceptor. No higher-orchestrator callback follows.

Claim hard read-only isolation only when established by the product. Under broader permissions proceed only when hard isolation is unnecessary; compare relevant mutation-sensitive state proportionately and disclose limits. Tests can mutate state: necessary execution needs authority and isolation protecting the target. Distinguish concurrent authorized writes from reviewer mutation.

## Finding quality and correction rounds

Use [Review Change’s finding dispositions](../../review-change/SKILL.md#finding-dispositions) for evidence-backed failure scenarios, introduced/pre-existing scope and fixed, dismissed, authorized-deferred or unresolved findings. Read that section when reporting or resolving findings; it owns the substantive finding rules. Required blocking closure still needs the independent confirmation below, including a disputed dismissal; the actual acceptor resolves disputes and any amendment/waiver within their authority.

Batch coherent repairs. When successive fixes introduce consequential failures or review keeps uncovering the same unresolved mechanism, the executor reassesses the implementation/recovery approach and checks the affected failure paths before submitting another corrected target. Review should not become the executor's routine debugging loop. Carry the original findings and new failure evidence together; use focused advice only for a named consequential uncertainty under actual delegation authority. This is not a fixed round limit, automatic extra agent or approval gate: continue justified repairs within mandate and return reserved choices to the actual acceptor. Missing checks remain explicit, and required independent closure still applies. Do not convert a deferred required defect into acceptance or weaken a required fresh whole-change review. Carry applicable coverage and review the complete intervening delta through delivery as below.

## Coverage, correction and result

Initially inspect actual files/artifacts and the complete target diff with decision-critical dependencies. Assess criteria as satisfied, failed, not assessed or inapplicable with reason. Challenge wrong behavior, ineffective expectations and missing coverage, including a mismatch between a narrow contract and the original need. Sample only interchangeable artifacts with basis/limits. State what intended-use validation the evidence establishes and what remains for the orchestrator/user.

Include consequential approach, requirement, design, tool and guidance changes in that target, with their problem/evidence, authority, reason, original/revised basis, verification and pending assessment from the existing record. Check that amendments serve the intended outcome within the actual mandate rather than weakening a promise to pass; green code checks alone do not cover changed commitments or guidance. Explicit bounded improvement/amendment authority may already permit the change; do not demand another blanket human approval. Beyond-mandate choices return to the actual deciding actor; review grants no amendment or owner-acceptance power.

For corrections recover the exact baseline, findings and applicable coverage. Inspect the complete subsequent delta, affected interfaces/invariants/consumers and new verification. Carry still-applicable coverage; expand when recovery/impact requires it. Compaction alone does not erase coverage. Use a fresh reviewer context for a new substantive correction request; phase entry and individual edits create no review event. A full repeat review may independently verify fixes in the same pass without a compulsory preceding fix-verification review. Reuse still-applicable evidence rather than replay checks solely for freshness. A collection of component reviews cannot imply whole-task coverage; carry coverage only where the mandate permits it, and honor a specifically requested fresh whole-change review. Findings that block acceptance need independent confirmation of closure regardless of severity label. Before feature readiness, carry still-applicable independent coverage and obtain independent review of the complete intervening delta and affected surfaces through the final delivered target; owner checks cannot independently clear that delta. Batch corrections at a coherent target, not after every edit.

Keep repair with the executor/original compatible worker. Return an attributable recommendation tied to exact target and carried/new coverage: `ship`, `fix-first`, `rethink`, `blocked`, `failed` or `voided`, with decisive findings, gaps and residual risk. `ship` supports readiness; `fix-first` requires correction; `rethink` returns a consequential decision; `blocked` means review could not complete; `failed` supplies no review evidence; `voided` discards an invalid review. Missing necessary evidence prevents a supported verdict. Passing checks establish only their actual claim; a positive verdict cannot replace the orchestrator's assessment and intended-use validation.

For reviewer mutation preserve evidence, void the verdict and recycle the reviewer. Restore only within authority while protecting foreign work, then establish the affected baseline; unresolved restoration/attribution prevents reliance on that review.

For clarification of an issued report, recover its identity, target, findings and limits without resetting active work or changing settings. A new substantive request always starts fresh and carries the exact prior basis, original failure scenarios and applicable evidence. Context freshness grants no acceptance power and proves no correctness. Failed or invalid reviewer work remains recorded; never silently replace failure.

Continue unaffected work while required review is pending; only an authorized task-scoped waiver removes it. The actual acceptor resolves findings, checks evidence applicability and performs/obtains missing intended-use validation before recording completed-scope acceptance/closure. Owner/reviewer completion and transport acceptance alone establish none of those decisions. Merge/adoption return to the user in the orchestrator chat.
